# אורה CRM

מערכת CRM פנימית לקליניקת אורה (רפואה אסתטית, הרצליה): לקוחות, תורים, קריאות שירות, מסך ראשי לבעלים, וממשק לסוכן השירות בצ'אט.

- **אפיון:** [docs/PRD.md](docs/PRD.md)
- **תוכנית בנייה וסטטוס:** [docs/PLAN.md](docs/PLAN.md)
- **בדיקות (עובד / לא עובד):** [docs/QA.md](docs/QA.md)
- **אינטגרציה עם הסוכן (n8n):** [docs/integration/](docs/integration/)

## סטק

Next.js 16 (App Router, Server Actions) · Supabase (Postgres, Auth, RLS) · Tailwind 4 · Vercel.

## מה יש במערכת

| מסך | מה עושים בו |
|---|---|
| מסך ראשי | קריאות חדשות / בטיפול / לא משויכות / חורגות מ-48 שעות, קריאות לפי אחראית, תורים היום, אחוז "לא הגיעה" ב-30 יום |
| לקוחות | חיפוש לפי שם או טלפון, לקוחה חדשה (חסימת טלפון כפול), כרטיס לקוחה עם התור הבא, קריאות פתוחות ויומן פעילות |
| תורים | סינון לפי היום / השבוע / עתידיים / עבר, סטטוס וסיבת ביטול חובה |
| קריאות שירות | פתיחה, שיוך, התחלת טיפול (חובה אחראית), סגירה עם תאריך סגירה אוטומטי |
| צוות והרשאות | מנהלת בלבד: תפקיד (מנהלת / מטפלת / צפייה בלבד), השבתה, מחירון טיפולים |

ההרשאות נאכפות ב-RLS בבסיס הנתונים ולא רק בממשק. משתמשת חדשה נכנסת כלא-פעילה עד שמנהלת מפעילה אותה.

## הרצה מקומית

```bash
npm install
cp .env.example .env.local   # למלא URL ומפתח publishable של Supabase
npm run dev
```

בסיס הנתונים נבנה מהקבצים ב-`supabase/migrations/` לפי הסדר.

## אבטחה

- אין מפתחות בקוד. בדפדפן רק המפתח הציבורי (publishable), והגישה לנתונים נקבעת ב-RLS.
- הסוכן ניגש דרך n8n לשתי פונקציות בלבד (`agent_create_ticket`, `agent_next_appointment`). כל קריאה נבדקת מול hash של מפתח אינטגרציה, והמפתח עצמו שמור רק בכספת של n8n.
- כל הנתונים במערכת בדויים.
