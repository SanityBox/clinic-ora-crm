# תוכנית · שלב 37: לשונית הלקוחה החדשה נסגרת, והלקוחה נבחרת בטופס

## Context
אחרי שלב 36, רועי לחץ על "יצירת לקוחה חדשה" מטופס קריאה, שמר את הלקוחה, והלשונית החדשה נשארה פתוחה על כרטיס הלקוחה. בטופס המקורי הלקוחה כן הופיעה בבורר (החיפוש החוזר עובד), אבל עדיין צריך לסגור לשונית, לחזור וללחוץ על השם. הזרימה הצפויה היא שהלשונית נסגרת לבד והלקוחה כבר בחורה בטופס.

## הזרימה החדשה
1. **בבורר** (`src/components/customer-picker.tsx`): בלחיצה על "יצירת לקוחה חדשה" הבורר יוצר token אקראי ופותח `window.open("/customers/new?name=…&pick=<token>")`. בלי `noopener`, כי רק לשונית שנפתחה מסקריפט מותר לסגור מסקריפט. ה-`href` נשאר עם אותם פרמטרים, כך שגם לחיצה עם הגלגלת עובדת. הבורר מאזין ל-`BroadcastChannel("ora-customer-picked")` ומקבל רק הודעה עם ה-token שלו. כך, אם פתוחים כמה טפסים, רק הטופס ששלח את הבקשה בוחר את הלקוחה. כשמגיעה הודעה מתאימה ועוד לא נבחרה לקוחה: `setSelected(customer)` וניקוי החיפוש.
2. **`customers/new/page.tsx`:** קורא את `pick` (רק `[a-z0-9]{8,32}`), ומעביר אותו ל-`CustomerForm` כשדה נסתר.
3. **`saveCustomer`** (`customers/actions.ts`): בלקוחה חדשה עם `pick`, במקום redirect לכרטיס, מחזיר `{ picked: { id, full_name, phone } }`. הלקוחה כבר נשמרה, וזה רק משנה לאן הולכים אחרי השמירה. בלי `pick` הכול נשאר כמו היום.
4. **`CustomerForm`** (`customer-form.tsx`): כשמגיע `state.picked`, הוא שולח `{ token, customer }` בערוץ ומבצע `window.close()`. אם הדפדפן חוסם את הסגירה (למשל לשונית שנפתחה ידנית), מוצגת הודעה: "הלקוחה נשמרה ונבחרה בטופס. אפשר לסגור את הלשונית הזו", עם קישור לכרטיס.
5. **טלפון קיים בזרימה הזו:** ליד "הטלפון כבר שייך ל<שם>" מופיע גם כפתור **"לבחור אותה בטופס"**, שמשתמש באותו ערוץ וסוגר את הלשונית. הלקוחה הקיימת נבחרת, ולא נוצרת כפולה.
- `src/lib/errors.ts`: הוספת `picked?` ל-`ActionState`.
- החיפוש החוזר מ-36 נשאר כגיבוי.
